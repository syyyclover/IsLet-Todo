# M1 系统骨架验证记录

日期：2026-10-28。阶段状态：**开发中，尚未通过 M1 门槛**。本记录覆盖空任务系统骨架，不代表完整应用功能或最终性能验收。

## 环境与依赖

- Windows 11 专业版 x64，10.0.26100；Intel Core i5-13500H，12 核 / 16 逻辑处理器，约 31.8 GiB 内存。
- .NET SDK 10.0.403，项目本地安装在 `.tools/dotnet`；`global.json` 锁定 SDK，依赖以各项目 `packages.lock.json` 锁定。
- CommunityToolkit.Mvvm 8.4.2；Windows App SDK Foundation 2.6.4；xUnit 2.9.3；Microsoft.NET.Test.Sdk 18.11.0；VS 测试适配器 4.0.1。
- 版本来自实际查询微软 [.NET 10 发布元数据](https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json) 与 [NuGet v3](https://api.nuget.org/v3/index.json)，未采用预览包。
- 通知按[微软 .NET 应用通知文档](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/app-notifications-dotnet)注册回调，再调用 Register，激活派发至 UI 线程；自包含配置参考[官方部署文档](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/self-contained-deploy/deploy-self-contained-apps)。Foundation 包中的投影实际包含 AppNotifications、Builder、AppLifecycle。

## 已实现的 M1 能力

- WPF 深色胶囊、240×40 DIP 收起、360 DIP 展开；岛内设置和归档阶段占位。
- 悬停 150ms、离开 400ms、220ms 可中断尺寸动画；设置/归档页不因离开收起，遵循系统减少动画设置。
- 每用户命名互斥对象、当前用户限定命名管道、消息长度与读取超时限制、第二次启动转发。
- Windows Forms 托盘入口、主显示器固定左中右锚点、工作区及显示设置变化处理。
- 通知注册、主次进程激活路由、失败状态显示；Debug 中可发送测试通知，Release 编译排除测试入口与发送方法。
- Windows x64 自包含未打包目录发布；普通用户 manifest，PerMonitorV2。

“已实现”仅表示存在代码，鼠标、键盘、DPI 和通知交互仍以人工检查表为准。

## 已复现并修复的问题

1. 管道监听 await 捕获 UI 同步上下文，退出同步等待导致死锁。回归测试 `DisposalDoesNotWaitForUiSynchronizationContext` 首先超时失败，加入 `ConfigureAwait(false)` 后通过，整个套件 14/14 通过。
2. `OnExplicitShutdown` 下窗口关闭但进程与托盘未退出。真实进程 Smoke 首先失败（WM_CLOSE 后超过 5 秒仍在运行），Closed 协调 Shutdown 后相同检查通过。
3. 首次使用总包会引入未使用的 AI / ML / WinUI 依赖。改用同版 Foundation 子包，保留基线的 Windows App SDK 通知技术；目录从 324.82 MiB 降到约 203.24 MiB，尚未达到目标。
4. `dotnet publish -r win-x64` 与普通 restore 使同一锁文件的 RID 集合变化。统一声明 RuntimeIdentifiers，并用锁定还原和无还原发布验证。

另处理了审查提出的通知竞争风险：COM 次实例等待 NotificationInvoked 并转发参数；常规次实例不重复注册通知。该竞争场景及通知冷启动定位尚未实测，不能宣称已验收。

## 性能基线与偏差

- 首次 Foundation 发布包：进程创建到可见 HWND 约 11165ms；内部日志从 WPF Startup 起到显示窗口约 6366ms，其中通知注册累计 2807ms。进程启动前半段仍需进一步分析，不把阶段耗时当完整启动耗时。
- 后续热环境运行：内部日志 Startup 至显示约 2031ms，通知注册累计 282ms。此值不是冷启动验收结果。
- 发布目录总大小：203.24 MiB，超过 200 MiB 目标；保留简体中文/英文卫星资源，不手工删除运行依赖。
- 5 分钟空闲基线由 `scripts/Measure-Idle.ps1` 测量，原始 JSON 位于忽略的 `artifacts/idle-baseline.json`。实际采样 301.19 秒、60 个样本；整机平均 CPU 0.1498%，工作集最小 132.73 / 平均 144.71 / 最大 148.77 MiB。CPU 低于 0.5% 目标，工作集超过 120 MiB 目标。测量目录为 `m1-final`，与最终目录相比仅缺少启动早期接受 IPC 的修订，不将本结果冒充最终版本或完整数据集验收。
- 空任务骨架不代表 100 活跃 / 1000 归档任务或 8 小时稳定性。不得据此宣称完整产品低占用达标。

后续建议：优先分析进程到 WPF Startup 的启动耗时，评估延后非关键注册的收益；分析工作集与 WinRT 投影装载；评估官方支持的依赖裁剪路径。任何调整仍需遵守 WPF、通知、自包含发布和稳定依赖基线，不提高预算掩盖问题。
