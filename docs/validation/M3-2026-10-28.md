# M3 系统提醒与入口稳定性验证

日期：2026-10-28。基线前一提交 `ec3e7d9`，分支 `feat/m2-task-persistence`。

## 修改与证据

- 续期、完成、归档会切换 IsBusy，AddCommand 因此短暂禁用并触发模板淡化。先用断言复现入口不可用，再保持入口稳定，将忙碌期间点击添加延后到当前操作完成。三条 WPF 测试验证 IsEnabled 不发生切换、列表无 Reset、添加请求最终进入编辑。按 ID 同步列表避免整表清空重建。
- 正式提醒走 Windows AppNotifications；稳定标识由任务 ID 和提醒版本组成，补提醒可合并摘要；只有 API 接受才记录已提交。系统免打扰不使用自制弹窗绕过。失败按 10 秒、60 秒重试，最多三次，最终失败有岛内反馈。
- 每次执行复查任务、版本和归档点；提醒调度仍采用单次事件定时器与 60 秒校准。独立审查发现发送前取消会错误耗尽次数，新增失败测试后调整为明确发送结果后才计次。系统提交与 SQLite 提交仍有不可原子化窗口，使用稳定通知标识降低重复可见提醒，不能承诺严格一次投递。
- 通知点击通过当前用户单实例 IPC 路由，加载前保留任务定位参数，不让普通 show 覆盖。加载后展开并选择活跃任务；已归档或不存在时给出状态提示。
- 位置与动画设置用 SQLite 串行事务保存；登录启动使用当前用户 Run 注册项及加引号的绝对路径，失败回滚控件状态。未自动为用户开启登录启动。
- 全屏监听使用前台与窗口事件，按目标显示器物理边界判断，排除桌面、任务栏和自身；无高频轮询。隐藏不清空编辑草稿，退出全屏恢复。
- 归档单项/批量删除都在岛内确认，取消不写数据。旧附件存在时拒绝整个删除事务，不删除来源文件或副本；附件一致性清理仍在 M4。
