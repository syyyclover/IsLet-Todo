# M2 添加入口与统一样式修复

日期：2026-10-28。用户反馈打开应用未看到添加入口，并要求所有 UI 与控件保持统一、美观。

## 原因与处理

本机已有 `user_version=1` 数据库，任务字段为 `archive_at_utc` 等 snake_case 格式；原 M2 迁移仅覆盖 PascalCase 字段格式，创建索引时报 `no such column: ArchiveAtUtc`。启动捕获异常后没有接入任务服务，添加命令无法进入编辑。原自动化测试只覆盖新库和另一种 v1 模型，未覆盖这套历史结构。

增加事务内字段兼容迁移，保留任务、置顶、提醒以及附件和待清理关联记录。迁移前使用 SQLite 一致性备份；失败回滚，不清空用户数据库。迁移测试先复现同一错误，再修复通过。本机新版启动后 schema 为 2，`quick_check` 为 `ok`，启动日志未再出现本次 SQLite 错误；没有读取或向日志输出任务正文。

加载期间禁用添加入口，加载失败自动展开岛内错误信息；SQLite 日志补充数字错误码，不记录原始异常正文或用户路径。

## 视觉与可用性

沿用需求中的深色胶囊与小面积绿色强调色。展开页使用横向主按钮“添加日程”，空列表显示操作引导。所有页面的按钮、输入框、复选框、列表行、提示和滚动条共用 `Themes/IslandTheme.xaml`；统一圆角、字号、间距、焦点及禁用反馈。任务操作使用同一套线性矢量图标，置顶以强调色标识。原生表面大小和开合动画实现未改动。

真实 WPF 窗口测试验证添加按钮可见、可用、至少 300×32 DIP，并通过按钮自动化 peer 的 Invoke 进入编辑。额外覆盖存储加载前后与忙碌时的命令可用性。测试生成并人工检查空列表、编辑、任务、设置与归档渲染图；图片存放在忽略的 `artifacts/ui-m2-fix/`，不提交用户数据或构建产物。

## 验证与限制

- Release 全套测试：77 项通过，无跳过（Domain 19、Application 10、Infrastructure 22、WindowsIntegration 4、Presentation 22）。包含原 12 项动画回归。
- Release 自包含发布成功，输出仍为 `artifacts/publish/m2-win-x64/`；已用新版启动并成功迁移本机数据库。
- 需求视觉基线与开发计划已同步统一控件要求，未改变时间规则或性能预算。
- 电脑控制工具未获应用操作授权，因此没有宣称本轮完成真实鼠标、键盘或多 DPI 验收；窗口布局、按钮调用测试与渲染检查不能替代这些验收。历史性能和发布门槛继续保留。
