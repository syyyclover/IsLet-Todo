# 时间选择与交互修复验证

日期：2026-10-28。用户提出五项反馈：倒计时与续期缺少动效、不能设置时间、输入裁切、单任务完成失败、设置和归档层级不符合预期。

## 修改

1. 沙漏每 3.4 秒翻转，沙量表达保留窗口比例；提示简化为剩余时长，续期写入成功后缩放和翻转。仅任务页可见且动画启用时运行，隐藏、离页、卸载或减少动画时停止。没有增加收起后台动画；可见控件循环动效按用户反馈更新需求基线，性能预算不变。
2. 日期、小时、分钟三列支持鼠标滚轮、拖动、上下键及上下按钮。默认下一个半小时，确认时重查未来时间、365 天范围和夏令时，确认前不改变任务时间。SQLite 保存与移除已覆盖，保留编辑既有逾期任务文字的能力。正式 Windows 通知投递仍未完成。
3. 输入框取消固定高度，减少垂直内边距，内容宿主拉伸；真实 WPF 布局检查文本宿主高度并渲染中文和 Emoji。时间选择时暂时隐藏标题和保存行，确认或取消后恢复，防止确认按钮被挤出岛。编辑确认仍在岛内。
4. 用旧库 NOT NULL 设置表复现唯一置顶任务完成时 SQLite Error 19；清除置顶改为删除对应键，避免写入 NULL。验证完成、恢复、重复取消置顶、重启及其他设置保留。不删除任务或清空数据库。
5. 日程、归档、设置采用固定同级页签，内容水平滑动 220ms；切换可中断，编辑未保存时继续保护草稿。保持原生窗口表面及开合动画实现。

## 验证

Release 全套测试 93 项通过，无跳过：Domain 19、Application 10、Infrastructure 23、WindowsIntegration 4、Presentation 37。覆盖时间模型、SQLite 保存、旧库约束、左右切换中断、输入布局、沙漏时钟生命周期、减少动画及原 12 项开合动画回归。存储约束与同层切换先复现失败再修复；时间模型首次运行因 PATH SDK 不匹配受阻，改用项目本地 SDK 后测试通过，未将受阻运行记为通过。

整合时发现控件本地静态资源缺失导致窗口构造失败；为时间控件合并统一主题后，窗口及全套测试通过。渲染结果位于忽略的 `artifacts/interaction-review/`；人工检查输入、时间滚轮及页面布局，测试未向用户数据库添加数据。

实际命令：项目 `.tools/dotnet/dotnet test TaskIsland.slnx -c Release --no-restore`；`dotnet publish src/TaskIsland.Presentation -c Release -r win-x64 --self-contained true --no-restore -o artifacts/publish/m3-interaction-win-x64`（dotnet 均为项目本地 SDK）。自包含发布成功。旧进程保持运行，未强制关闭可能存在草稿的用户界面；使用新包前须通过托盘退出旧版。

本轮未完成真实鼠标滚轮、拖动、多 DPI、长时间性能、通知点击、干净机器及全屏验收。测试和渲染不能代替这些检查；新动效的可见状态资源开销尚未测量，原 M1 发布门槛与 M3 正式通知、设置仍保留。
