# 开合边界闪动修复

用户反馈：上一版动画稍流畅，但打开、关闭时仍会闪一下。

## 复现与修复

1. 订阅真实 WPF `RectangleGeometry.Changed`，检查整个展开/收起过程的宽度单调性。旧代码在动画完成时先清除时钟，再写终值，短暂暴露旧基值；展开、收起两项测试都失败。改为先保存当前值或最终基值，再移除动画时钟，两项通过。内容透明度、位移也按相同顺序处理，防止反向或完成瞬间跳回旧值。
2. 原方案虽然没有逐帧 resize，但一轮开合边界仍产生 4 次 SizeChanged。现在从首次显示起保持岛最大范围内的固定原生表面（正常工作区为 360×295 DIP），开合只改绘制形状。真实原生窗口矩形 `GetWindowRect` 与 SizeChanged 测试验证开合边界不再变化。
3. 定位采用所配置的宽高，避免读取布局尚未更新的 ActualWidth/ActualHeight。显示器、DPI 或工作区改变时仍重新配置视口；左、中、右锚点在重复开合后的屏幕位置测试通过。

## 明确的取舍

之前方案在收起结束把原生窗口缩回 240×40；本轮为消除分层窗口表面重建，改为保持最大岛范围的原生表面。收起时**可见胶囊仍为 240×40**，余白像素 alpha 为 0，内容隐藏且不参与点击。不会创建覆盖屏幕的透明窗口。

这会保留最大岛画布的表面内存；本轮不宣称空闲内存或最终性能目标已达标。跨进程透明区穿透及用户机器上的实际呈现仍需人工复验，零 alpha 渲染测试不替代该交互验收。

## 检查结果

- 全套 26/26 通过：Application 10、WindowsIntegration 4、真实 WPF 12。
- 原生窗口稳定、开合形状单调、两个方向的中途反向、淡出保留页面、减少动画、透明余白、三个锚点均有回归测试。
- 独立审查指出固定 host 后旧反向测试仅断言 host 宽高会失效；已强化为检查裁剪形状、内容可见性和透明度，并补反方向测试。
- Release 构建此前本轮已验证 0 警告、0 错误；最终修订仅增加测试。自包含发布成功。
- 高 DPI 下 WPF 的 DIP 高度可能为 295.333…，因此稳定性测试检查真实物理窗口矩形，避免将 DIP 像素舍入误判为窗口变化。
- 最终发布包进程级 Smoke 通过：可见窗口创建、二次启动转发、关闭完整退出；本次热环境进程到可见窗口约 1562ms，不作为冷启动验收。整体 M1 的干净机器、通知点击和性能门槛继续保留。
