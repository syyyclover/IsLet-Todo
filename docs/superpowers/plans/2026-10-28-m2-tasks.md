# M2 任务与持久化 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task, with TDD and a final independent code review.

**Goal:** 岛内可添加、编辑、完成、置顶、续期、归档和恢复任务，重启数据一致，时间规则与持久化失败路径可自动验证。

**Architecture:** Domain 提供不可变任务及纯规则；Application 编排串行事务和可替换 TimeProvider；Infrastructure 执行后台 SQLite、版本迁移与一致性备份。Presentation 通过任务服务更新界面，Windows 集成仅转发恢复/系统时间校准。

**Tech Stack:** 既有 .NET 10 / WPF / MVVM；Microsoft.Data.Sqlite 10.0.14；xUnit；官方 FakeTimeProvider 10.11.0（仅测试）。

**Spec:** `IsLet_Todo.md` 第 2.1–2.8、3.2–3.6、4.2–4.3、5.2 节；`docs/DEVELOPMENT_PLAN.md` M2。

## Global Constraints

- 结束时间与归档时间独立，UTC Unix 毫秒存储，续期不累计、不增加提醒版本。
- 无结束时间从创建/移除/恢复操作起 24 小时；有结束时间在结束后 24 小时归档。
- Unicode 文本元素上限 200，摘要 9；最多单任务置顶。
- 所有写入经统一串行事务，成功后更新 UI；迁移前 SQLite BackupDatabase，未知版本或损坏不清空。
- 正式通知发送、完整滚轮和附件在 M3/M4 接入；本轮仅持久化待提醒版本，不伪报发送成功。

## Review Focus

- 只修改到期任务文字不能被“必须未来时间”校验拦住，也不能改变归档时间或提醒版本。
- 归档、恢复和旧提醒版本必须原子变更，系统时间跳变不得重复排入同版本提醒。
- SQLite 回调异常必须回滚；数据库损坏/新版本/迁移失败不覆盖原文件。
- 快速并发操作不能丢更新，退出等待已接受写入，UI 不运行同步 SQL。
- 编辑保存失败保留输入；离开未保存编辑需岛内确认；后台归档不抢焦点。
