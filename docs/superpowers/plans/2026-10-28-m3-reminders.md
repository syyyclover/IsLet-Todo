# 添加入口闪烁与 M3 系统能力

用户要求先修复续期、完成、归档使添加入口闪烁，再推进下一阶段并联合验证。

根因验证：忙碌状态触发 AddCommand CanExecute 的禁用淡化；先运行失败断言，再保持入口可用，将忙碌期间的添加请求延迟到事务结束。列表同步改为按 ID 增删、移动和更新，避免整体清空造成空状态和沙漏重建。

后续按现有基线实施 M3，不进入附件扩展：串行提醒调度与重试、Windows 发送器与稳定标识、通知激活定位、SQLite 设置存储、HKCU Run 登录启动、事件驱动全屏隐藏、岛内删除确认。为已有旧附件增加拒绝删除保护，M4 才实现清理队列。

三个独立范围按并行技能分工：提醒事务管线、平台通知、平台自启动/全屏；主任务负责入口修复、界面和 App 装配。代码审查发现发送前消耗最后一次预算和启动参数覆盖，均在验证前处理。

验证：失败→通过回归、模拟时钟重试、临时数据库/注册表测试、真实 WPF 布局和命令、完整 Release 测试及发布。用户已通过托盘退出旧版；启动新版进行联合验证。真实系统通知、点击与全屏以人工结果为准，不能用模型测试标记通过。
